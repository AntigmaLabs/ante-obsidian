# Tmd 用户使用文档

Tmd 是一个面向 Obsidian 桌面版的 Markdown 插件。它把本地 Ante 运行时接入到笔记编辑流程中，帮助你直接在笔记里改写、补充、规划和审阅 Markdown 内容。

本文档面向普通用户，重点说明 Tmd 能做什么、从哪里触发、结果会出现在哪里。

## 插件能做什么

Tmd 当前主要提供 6 类用户可见功能：

1. 在笔记中通过 `@ante` 触发 AI 处理当前内容。
2. 通过右键菜单或命令面板，对当前笔记直接运行预设任务。
3. 在 `Tmd Results` 中查看 Markdown 改动结果和 Diff 对比。
4. 在 `Chat with Ante` 中发起自由提问或连续追问。
5. 在 `Ante Terminal` 中以更接近终端的方式与 Ante 交互。
6. 在插件设置中配置本地 Ante 运行时、provider、model 和凭据。

## 功能一：笔记内联触发

你可以直接在 Markdown 笔记里输入以下触发词：

- `@ante`

### 适合做什么

- `@ante`
  适合让插件直接处理当前段落、当前选区，或当前笔记里的具体内容，例如润色、改写、补全、整理结构。

对于研究或规划任务，请使用右键菜单或命令面板。

### 触发后的表现

- 如果你当前选中了文字，Tmd 会优先把选区作为处理上下文。
- 如果没有选区，Tmd 会自动抓取当前光标所在段落作为上下文。
- 插件会先在笔记中插入一个“正在运行”的占位块。
- 如果 Ante 返回的是文本结果，占位块会被替换成最终内容。
- 如果 Ante 返回的是文档修改建议，Tmd 会直接应用修改，并在笔记中显示“已应用”的提示块。

### 典型使用方式

- 在一段草稿后面输入 `@ante`，让它重写该段内容。
- 在一个主题标题下，通过右键菜单里的 `@ante research` 补充研究笔记。
- 在会议记录或需求草稿中，通过右键菜单里的 `@ante plan` 把想法整理为执行计划。

## 功能二：右键菜单快速运行预设任务

在 Obsidian 编辑器中右键，可看到 Tmd 提供的快捷入口：

- `@ante`
- `@ante research`
- `@ante plan`
- `Chat with Ante`
- `Open Ante Terminal`

### 这类入口的特点

- 不需要在正文里手动输入触发词。
- 更适合对“当前整篇笔记”或“当前选中文本”直接发起处理。
- 如果任务返回的是 Markdown 修改建议，Tmd 会尝试自动应用。
- 如果自动应用失败，或你需要复核结果，可以去 `Tmd Results` 查看具体 Diff。

## 功能三：命令面板入口

Tmd 注册了几个常用命令，可以从 Obsidian 命令面板直接调用：

- `Open Tmd Results`
- `Chat with Ante`
- `Open Ante Terminal`
- `Run @ante on current note`
- `Run @ante research on current note`
- `Run @ante plan on current note`

### 适用场景

- 你习惯用命令面板而不是右键菜单。
- 你希望快速打开结果面板、控制台或终端面板。
- 你想对当前笔记重复执行同一类任务。

## 功能四：Tmd Results 结果面板

`Tmd Results` 是查看任务结果的核心面板。它既能展示纯文本输出，也能展示 Markdown 改动的 Diff。

### 你可以在这里看到什么

- 当前任务的状态
- 纯文本结果
- 每个改动项对应的文件位置
- 每个改动项的增删行数统计
- 统一 Diff 预览

### 它能解决什么问题

- 判断 Ante 改了哪里
- 快速检查改动是否符合预期
- 区分是“替换选区”、“追加内容”、“替换整篇文件”还是“新建文件”

### 关于改动类型

Tmd 支持处理以下几类 Markdown 变更：

- `replace-selection`
- `append-block`
- `replace-file`
- `create-file`

### 为什么这个面板重要

当插件不是直接返回文本，而是准备对笔记做结构性修改时，`Tmd Results` 就是你检查结果、理解改动范围和定位文件的主要界面。

## 功能五：Chat with Ante

`Chat with Ante` 提供一个聊天式自由提问界面，适合不直接改文档、而是先和 Ante 对话。

### Chat 的主要能力

- 手动输入任意问题或任务
- 自动带上最近一次可用的笔记上下文
- 保留聊天时间线
- 支持在已有会话基础上继续追问
- 展示文本回复、日志和已生成的改动提示

### 适合的使用方式

- 先问思路，再决定要不要改文档
- 对刚刚执行过的任务继续追问
- 做探索性讨论，例如“还有哪些角度可补充”

### Chat 和内联触发的区别

- 内联触发更像“在笔记里直接动手”
- Chat 更像“先聊清楚，再决定是否改”

## 功能六：Ante Terminal

`Ante Terminal` 是一个更接近终端体验的交互面板。它会显示命令式输入、输出流、系统日志、运行状态，以及需要时的工具授权按钮。

### Terminal 的主要能力

- 以对话/终端样式连续发送 prompt
- 看到运行中的流式输出预览
- 查看系统日志和错误信息
- 在需要时批准或拒绝 Ante 的工具调用
- 任务完成后跳转到 `Tmd Results` 查看改动结果

### 工具授权

当 Ante 在执行过程中需要调用工具时，Terminal 里可能出现授权卡片。你可以选择：

- `Approve once`
- `Allow session`
- `Deny`

这适合对安全性、可控性要求更高的使用场景。

## 上下文如何确定

Tmd 会尽量根据你的当前编辑状态，自动推断应该把什么内容交给 Ante：

- 有选区时，优先使用选区
- 没有选区时，可能使用当前段落
- 在 Chat with Ante 或 Terminal 中，优先使用最近一次捕获到的笔记上下文

这意味着你通常不需要手动复制粘贴整段笔记，只要把光标放在合适位置，或先选中目标内容即可。

## 配置相关功能

除了编辑功能外，Tmd 还提供一些运行配置项，方便你接入本地 Ante 环境。

### 可配置项包括

- Ante 可执行命令
- Ante 启动参数
- 工作目录
- 是否自动批准 Ante 工具调用
- 是否沿用 `~/.ante/settings.json` 里的 provider 和 model
- 手动指定 provider 和 model
- Gemini API Key 或其环境变量名
- 是否开启 mention trigger 调试提示

### 对用户的意义

- 你可以让 Tmd 复用已有的 Ante 配置。
- 也可以在插件内部单独指定模型和供应商。
- 如果你的环境比较复杂，可以通过工作目录和命令参数做兼容。

## 一个典型工作流

1. 打开一篇 Markdown 笔记。
2. 选中一段内容，或者把光标放到目标段落。
3. 通过 `@ante`、右键菜单或命令面板发起任务。
4. 如果结果是直接文本，会在笔记里或结果面板中显示。
5. 如果结果是文档修改，去 `Tmd Results` 检查 Diff。
6. 如需继续讨论，打开 `Chat with Ante` 或 `Ante Terminal` 追问。

## 使用前提

Tmd 本身不直接提供模型能力，它依赖你本机可用的 Ante 运行环境。

使用前请确认：

- 你使用的是 Obsidian 桌面版
- 已正确安装并启用 Tmd
- 本机可以运行 `ante`
- Ante 对应的 provider、model、API 凭据已经配置好

如果 Ante 本身不可用，Tmd 也无法正常工作。

## 总结

如果把 Tmd 的功能概括成一句话，它就是：

“把 Ante 接到 Obsidian 的 Markdown 编辑流程里，让你能在笔记内触发 AI、查看改动 Diff、直接应用或继续追问。”

对于日常使用，最值得优先掌握的是这三件事：

- 在笔记里使用 `@ante`，以及通过右键菜单或命令面板使用 `@ante research`、`@ante plan`
- 在 `Tmd Results` 中检查修改结果
- 在 `Chat with Ante` 或 `Ante Terminal` 中做追问和深入交互
